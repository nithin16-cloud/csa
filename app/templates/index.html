ENGINEERING HIGHLIGHT

Zero Double-Booking Guarantee

How our database-backed concurrency engine ensures multiple users can never book the exact same seat.

1. Atomic Conditional Updates

Every seat update executes with WHERE is_booked = 0 condition. If another transaction books it first, rowcount = 0 and the reservation safely fails with HTTP 409.

2. SQLite Immediate Locks

Writes use BEGIN IMMEDIATE with SQLite Write-Ahead-Logging (WAL) mode to reserve write locks upfront, completely preventing race windows between reading and booking.

3. Hard Database Constraints

Enforced UNIQUE(flight_id, seat_number) and UNIQUE(flight_id, seat_id) table constraints guarantee that no physical duplication can ever enter the database.
